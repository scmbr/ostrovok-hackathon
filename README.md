# Бронь без сюрпризов

Прототип агентной системы для трека «О!дин шаг до идеального отеля» (Хакатон Островка 2026), регион — Барселона, 60 демо-отелей.

Система знает об отеле то, чего нет в карточке: с какого этажа и с какой стороны видно море, насколько тихо ночью с каждого фасада, сколько минут пешком до пляжа и метро, что открыто ночью. Каждое значение — **факт** с источником, методом, уверенностью, датой и сроком годности; его можно разложить на свидетельства (расчёт по кадастру и картам шума, ответ отельера, анкеты гостей) и увидеть, кто что утверждает. Что не удаётся вычислить, агент спрашивает у отельера и принимает свободный ответ. LLM понимает язык и выбирает инструменты, но **никогда не является источником факта**.

Гость описывает желание словами, получает выдачу с объяснением («совпало / шанс / под вопросом, откуда известно»), сравнивает отели относительно своих желаний, видит контракт ожиданий и бронирует категорию номера с пожеланием («восточная сторона, этаж 4+»). Отельер видит, что система узнала о его отеле, подтверждает, исправляет и отвечает один раз для всех.

## Быстрый старт

```sh
git clone https://github.com/ostrovok-hackathon-2026/tima-mechty.git
cd tima-mechty
cp .env.example .env
docker compose up --build
```

Откройте http://localhost:8080. Проверка: `curl http://localhost:8080/health` → `{"status":"ok"}`.

| | Замер на чистом Docker (без кеша слоёв, `build --no-cache`) |
|---|---|
| Сборка образа | 3 мин 33 с (Node, Go и Alpine собираются с нуля; базовые образы уже были загружены) |
| Старт до `/health` 200 (первая инициализация PostGIS и загрузка сида) | 2 мин 36 с при первом запуске; 2 мин 14 с на новом томе БД, когда образы уже собраны |
| Всего от `git clone` до рабочего интерфейса | ≈ 6 мин 10 с (замер на ноутбуке: 8 потоков, 8 ГБ памяти для Docker, быстрый канал) |
| Память в работе | ≈ 150 МБ в покое (приложение 10–20 МБ, PostGIS 115–135 МБ); ноутбуку достаточно 2 ГБ свободной памяти |
| Диск | ≈ 0,85 ГБ: образ PostGIS 609 МБ, образ приложения 36 МБ, том БД ≈ 195 МБ; кеш сборки Docker сверх этого |

Ориентир организаторов — не более 10 минут. Платформа образов `linux/amd64` (на Apple Silicon первая инициализация PostGIS под эмуляцией занимает дольше). Ключ LLM для запуска не нужен. Порт БД на хост не публикуется, поэтому занятый локально 5432 запуску не мешает.

## Режим без LLM

Без `LLM_API_KEY` (по умолчанию в `.env.example`) приложение работает **в режиме кеша**: в шапке интерфейса видна плашка, демо-сценарии отвечают сохранёнными ответами модели (записаны живой моделью `gpt-4o-mini` на данных этого же сида), а свободный текст разбирается правилами по синонимам из реестра характеристик. Что отвечает из кеша, что по правилам — `docs/dialog.md`; воспроизведение без промахов проверяют `make test-replay` и `make test-replay-dialog`.

**Провайдер и модель:** OpenAI, `gpt-4o-mini`. `LLM_BASE_URL` совместим с любым OpenAI-совместимым API, в том числе локальным (Ollama, vLLM): укажите его адрес и имя модели в `LLM_MODEL`.

**Ключ для жюри** передан отдельно, в зашифрованном файле `secrets.env.age` в корне репозитория (age, публичный ключ организаторов). Расшифруйте его в `.env` в корне и запустите как обычно:

```sh
age -d -i <закрытый ключ> -o .env secrets.env.age
docker compose up --build
```

Без ключа работает режим сохранённых ответов: демо-сценарии отвечают из кеша. Открытый `.env` в git не попадает. С ключом модель разбирает язык, выбирает инструменты и пишет вводную к выдаче (проверяется кодом по числам и названиям отелей); значения характеристик она записать не может — такого инструмента у неё нет.

## Переменные окружения

Все переменные лежат в `.env.example` без значений. Пустое значение (или отсутствие `.env`) означает умолчание из таблицы: `docker compose` подставляет его через `${VAR:-умолчание}`, Go-конфиг делает то же вне Docker.

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `LLM_BASE_URL` | пусто → `https://api.openai.com/v1` | OpenAI-совместимый endpoint (в том числе Ollama, vLLM) |
| `LLM_API_KEY` | пусто | пусто — режим кеша, без вызовов LLM |
| `LLM_MODEL` | пусто → `gpt-4o-mini` | имя модели; кеши записаны на ней |

Служебные переменные задаёт Compose, менять их не нужно: `DATABASE_URL` (`postgres://tima:tima@db:5432/tima`, пароль БД учебный, порт БД наружу не публикуется), `PORT` (`8080`), `SEED_FILE` (`/app/seed.sql.gz`, задан в `Dockerfile`).

Повторный старт дублей не создаёт.

- Как собран сид: откуда данные, какие запросы, когда и по каким лицензиям (OpenStreetMap, Catastro, Open Data BCN, Open-Meteo) — **`docs/data.md`**.

После сценариев, которые пишут данные (ответы, брони, репутация), БД можно вернуть к сиду: `docker compose down -v && docker compose up --build` (в чистом проекте Compose; рабочий том с таблицами вне сида так удалять не стоит).

## Как система определяет правду

Источники ошибаются по-разному: открытые данные устаревают, отельер приукрашивает, гости шумят. Поэтому хранится не «значение», а **свидетельства** (`evidence`), а факт собирается из них. Подробно, с формулами и всеми параметрами — [`docs/truth.md`](docs/truth.md).

```
r = база_источника × (0,5 + репутация автора) × асимметрия × свежесть     (в пределах 0,05…0,97)
вклад L = ln(r / (1 − r))                                                  (при r ≤ 0,5 вклад 0)
S(значение) = Σ L свидетельств «за» − Σ L свидетельств «против»
уверенность = 1 / (1 + e^−S)
```

- **База:** расчёт по кадастру или карте шума 0,85, по OSM 0,6, отельер 0,8, гость 0,7.
- **Асимметрия:** слово отельера «в пользу отеля» (вид есть, тихо, питомцы можно) умножается на 0,75, признание недостатка — на 1,0.
- **Зависимые источники** (общая `independence_group`, например два набора одной карты шума 2017 года) считаются один раз.
- **Числа не голосуют:** минуты и дБ берутся из расчёта, ответы людей служат проверкой.
- **Конфликт** — обе стороны весят не меньше порога θ; среднее не берётся, создаётся запись и вопрос тому, кого дешевле спросить.
- **Репутация автора (судья):** `trust = (совпадения + 1) / (всего + 2)`. Утверждение сверяется с фактом, собранным из свидетельств **без этого автора**, если уверенность такого факта ≥ 0,75. Несогласие с расчётом само по себе отельера не наказывает: несколько надёжных гостей против расчёта считаются сигналом пересчёта.

**Пример — отель 156, категория «Sea View».** Название категории — утверждение отеля «вид есть» (`full`); расчёт по кадастру тоже говорит `full`, а три надёжных гостя с этажей из брони сообщили, что вид закрыт (`none`). Цифры — с демо-сида.

| Свидетельство | Значение | Расчёт надёжности | r | Вклад L (в пользу `none`) |
|---|---|---|---|---|
| расчёт по кадастру | full | база 0,85 | 0,85 | −1,73 |
| отельер («Sea View», репутация 0,50) | full | 0,8 × (0,5 + 0,50) × асимметрия 0,75 | 0,60 | −0,41 |
| гость × 3 (репутация 0,67 каждый) | none | 0,7 × (0,5 + 0,67) | 0,82 | +1,49 × 3 |

`S(none) = 3 × 1,49 − 1,73 − 0,41 = 2,34`, уверенность `σ(2,34) = 0,91`: факт категории — «вида нет». В споре участвует утверждение отельера, поэтому порог конфликта понижен (θ = 0,3), обе стороны его превышают — открыт **конфликт**, а не усреднение. Судья репутации — факт без отельера (гости + расчёт): `S(none) = 4,48 − 1,73 = 2,75`, уверенность 0,94 ≥ 0,75. «Sea View» с ним расходится, доверие отельера `(1 + 1) / (2 + 2)` = **0,50**; после честного «нет» в кабинете `(2 + 1) / (2 + 2)` = **0,75**, а его слово переходит на сторону `none` (вклад +3,48). Конфликт при этом остаётся открытым: гости и отельер против расчёта.

Гости при этом поставили факт фасада на пересчёт (`recompute_tasks`): расчёт подтвердился (нового здания в данных нет), и отельеру ушёл вопрос про деревья, леса и стройку.

## Масштабируемость

- **По характеристикам:** реестр `backend/registry/*.yaml` (формат — `docs/registry.md`): ключ, уровень (отель / фасад / категория / район), стратегии с базой надёжности и группой независимости, правила конфликта, синонимы для поиска. Новую характеристику можно добавить файлом или **текстом** («есть ли рядом круглосуточный магазин»): LLM выбирает только из существующих инструментов, результат проходит ту же проверку, сервер подхватывает её без пересборки (экран «Реестр»). Нет подходящего инструмента — стратегия «спросить отельера». Желания, которых нет в реестре, копятся в `unmet_wishes`.
- **По регионам:** регион — сущность (`regions`: контур, районы), у региональных таблиц `region_id`, `collect -region <код>`; метрическая проекция — одна константа. Второй регион в демо не включён.
- **Источники — адаптеры за портами с цепочкой запасных вариантов:** высоты — кадастр → OSM → по умолчанию; шум — городская карта → карта шума ЕС → оценка по OSM; в регионе без авторитетных источников уверенность ниже и вопросов отельеру больше.
- **По объёму:** расчёт — один раз на здание и по сроку годности; вопросы отельеру — по ценности (спрос × неуверенность × влияние) и недельному бюджету, дайджестом; «похожий» и ранжирование — без LLM.

## Качество

Размечено 18 демо-отелей (публичные страницы по веб-поиску, не натурный эталон). Таблицы, оговорки и «что калибровать дальше» — [`docs/metrics.md`](docs/metrics.md). Команда: `cd backend && go run ./cmd/collect metrics`.

- **Вид на море:** береговые отели (до 400 м от берега) — 8 из 8, все 17 оценённых меток — 16 из 17 (94 %); единственный промах — башня за подиумом (известное ограничение расчёта). Городские отрицательные метки почти тривиальны, поэтому главная цифра — по береговым.
- **Шум ночью не измерен:** в публичных описаниях оценимых меток 2 и 3 из 18.
- **Покрытие фактами уровня отеля** (60 демо-отелей): `sea_view` 100 % (уверенных 97 %), `noise_night` 100 % (65 %), маршруты 98 %, ночные сервисы 100 %. Одноисточниковые маршруты и ночные сервисы уверенными (≥ 0,75) не становятся по построению (базы 0,7 и 0,6).
- **Вопросы отельерам:** из 150 кандидатов отсеяно ценностью и бюджетом 6 (4 %); по 6 из 8 характеристик с вопросом отправлен хотя бы один.

## Стек и структура

Backend — Go, Clean Architecture (`backend/`: `domain` → `usecase` → `adapter`), Postgres 16 + PostGIS (`postgis/postgis:16-3.4`), SQL и пространственные выборки только в `adapter/repository/postgres`. Frontend — React + Vite + TypeScript, Feature-Sliced Design (`frontend/`), статика встроена в бинарник через `go:embed`. Образ: node → golang → alpine, процесс под пользователем `app` (uid 10001), порт 8080. Правила для разработчика и список команд — `CLAUDE.md`, контекст и журнал решений — `docs/PROJECT_CONTEXT.md`.

## Для разработчика

`cmd/collect` и `make test-replay*` ходят в БД с хоста, поэтому порт 5432 публикуется отдельным файлом `docker-compose.dev.yml` (`127.0.0.1:5432`). `make up` / `make down` запускают стек с ним; основной `docker-compose.yml` порт БД не открывает. Вручную: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build`. Стенд `demo` (`localhost:8081`, БД `5433`) — `docker-compose.demo.yml`, см. `CLAUDE.md`.

Полезные команды: `make up` (с портом БД), `make down`, `make seed`, `make test`, `make test-replay`, `make test-replay-dialog`.
