# Гости «Гуру»: анкеты, репутация гостя, сигнал пересчёта

Гость — третье семейство источников после расчёта по открытым данным и отельера (раздел «Источники и логика
определения правды» в `PROJECT_CONTEXT.md`). Гости видели сами, но их мало и они субъективны. Анкета короткая,
строго по ожиданиям брони.

## Заселения (мок)

`collect mock-stays` пересоздаёт гостей и брони демо-отелей (детерминированно от id отеля). У каждого отеля две
брони в разных категориях: гостя селят в ячейку «фасад × этаж» категории, при пожелании («море, фасад X, этаж N+») — туда,
где пожелание выполняется. Персона: честный (70 %) или ленивый. У приукрашивающих отелей (57, 143, 326) заселений нет:
их сценарий — репутация отельера. **Сценарий closed_view:** у первого демо-отеля с честной категорией «Sea View»
(расчёт гарантирует вид) три гостя closed_view в трёх разных ячейках сообщают, что вид закрыт (деревья, леса, стройка,
которых нет в открытых данных).

## Анкета

1–2 вопроса по ожиданиям брони (вид на море — да/нет, шум ночью — тихо/терпимо/шумно) и один **контрольный**
с ответом, который система знает. Баллы «Гуру»: 10 за ответ, одинаково за «да» и «нет»; небрежная анкета — 0.

**Контрольный вопрос** строится только по фактам, которые система знает (`walk_to_metro`, `walk_to_beach`): уверенность
не ниже 0,6, не stale, без конфликта и weak_disagreement. Скрытая истина мока (`mock_hotel_truth`) для него не
используется: система знать её не может, а иначе замеры точности на этапе 8 были бы испорчены. **Правило запаса**
(`domain.ControlMargin = 2`): вопрос «не дальше N минут пешком?» с правильным ответом «да» задаётся с N не меньше
вдвое большего факта (3 мин → N = 10), с ответом «нет» — с N не больше вдвое меньшего (12 мин → N = 5). Ближе — вопрос
не задаётся: погрешность расчёта (граф OSM, округление) не должна менять правильный ответ. Если по расчёту все ответы
честного гостя одинаковые, правильный ответ контрольного противоположный; нет запаса для противоположного — контрольный не
задаётся, чтобы честный гость не выглядел небрежным.

**Небрежность** (`domain.Careless`): анкета быстрее 8 секунд, все ответы одинаковые (при трёх и более), контрольный
вопрос провален. Несогласие с расчётом небрежностью не считается.

## Свидетельство и область

Ответ — свидетельство гостя (`author_type = guest`, база 0,7) о **категории** номеров с `details` из брони:
фасад, этаж, `booking_id`, `survey_id`. Свидетельство нужно только там, где ответ говорит о категории в целом: ответ
входит в свидетельства, если расчёт в ячейке брони даёт то же значение, что у категории в целом. Гость со 2-го этажа
(«моря не видно») категорию с видом с 4-го этажа не опровергает: ответ записан в анкете (`guest_surveys.scope`), но
свидетельством не становится. Ответы небрежных анкет тоже не становятся свидетельствами: с весом ленивого гостя (≈0,33)
они пробивали порог конфликта категории (θ = 0,3) и создавали конфликты на пустом месте. Небрежность снижает репутацию.

## Репутация гостя

`trust = (добросовестных анкет + 1) / (анкет + 2)`, пересчёт заново по всем анкетам (`reputation.Service.UpdateGuest`
через тот же `SaveTrust` и пересборку фактов, что у отельера). Добросовестная анкета — контрольный пройден и небрежности нет.
Один внимательный гость — 0,67, один ленивый — 0,33. Вес свидетельства в движке правды ∝ `0,5 + trust`. Наказывают
только контрольный вопрос и небрежность, не несогласие с расчётом: несколько надёжных гостей против расчёта — сигнал,
что мир изменился.

## Сигнал пересчёта

`collect guest-signals`: если **3 надёжных гостя** (`trust ≥ 0,5`, `domain.SignalMinGuests`, `SignalMinTrust`), чьи брони
попадают в область факта, независимо (по одному голосу с брони) ответили против расчёта в своих ячейках, факты
фасадов отеля помечаются `stale`, создаётся задача `recompute_tasks`, причина пишется в `agent_trace`
(`agent = guest_signal`, `mode = rule`). `collect recompute-tasks` запускает инструмент по отелю (для `sea_view` —
`sea-view`, на сиде по частям зданий), движок правды пересобирает факты, итог: `confirmed` (значения не изменились)
или `changed`. Если подтвердил расчёт (нового здания в данных нет — нормальный исход), а надёжные гости остаются против,
у категории остаётся конфликт «гости против расчёта» (обе стороны выше θ). Причину знает отельер: `collect hotelier-round`
создаёт вопрос по конфликту категории (деревья, леса, стройка).

## Ограничения

Заселения, ответы и длительность — мок. Контрольные вопросы — только по пешим маршрутам. Для анкет по шуму ответ
«шумно/терпимо» отправляется как значение enum без пожелания. Гости не видят ответов отельера. Профиль предпочтений,
согласие и «забыть» — этап 6–7.
