# Как система определяет правду

Черновик раздела для README. Реализация — `backend/internal/domain/truth.go` (чистая функция, тесты в `truth_test.go`), пересчёт всех фактов — `go run ./cmd/collect truth`.

## Принцип

Источники ошибаются по-разному: открытые данные устаревают, отельер приукрашивает, гости шумят. Поэтому система хранит не «значение», а **свидетельства** (`evidence`): кто, что и с какой надёжностью утверждает. Итоговый **факт** (`facts`) собирается из активных свидетельств. LLM автором свидетельства быть не может.

Факт содержит значение, уверенность (`confidence`), ссылки на свидетельства и вклад каждого из них (`evidence.contribution`): «уверенность 0,79: карта шума +1,73, оценка OSM −0,41».

## Формула

**1. Надёжность свидетельства.** База источника (`evidence.reliability`: расчёт по карте шума 0,85, по OSM 0,6, отельер 0,8) умножается на поправки и ограничивается `[0,05; 0,97]`:

```
r = база × репутация × асимметрия × свежесть
```

| Поправка | Значение |
|---|---|
| репутация автора-человека | `0,5 + trust` (от ×0,5 до ×1,5); новичок с trust 0,5 — ×1,0; у инструментов — ×1,0 |
| асимметрия | ×0,75 для утверждения отельера в пользу отеля (список «выгодных» значений — параметр характеристики; для `noise_night` это `quiet`); признание недостатка — ×1,0 |
| свежесть | линейно от ×1,0 в момент наблюдения до ×0,5 в `valid_until`; после срока остаётся ×0,5, факт получает признак `stale` (на пересчёт) |

**2. Вклад.** `L = ln(r / (1 − r))`. Надёжность ниже 0,5 информации не несёт, такой вклад считается нулевым.

**3. Зависимые источники.** Если у свидетельств одинаковый `independence_group`, учитывается только сильнейшее, у остальных вклад 0 (два набора карты шума BCN — одна модель 2017 года).

**4. bool и enum.** Для каждого значения `v`:

```
S(v) = Σ L (свидетельства за v) − Σ L (свидетельства за остальные значения)
```

Значение факта — с наибольшим `S`, уверенность — `σ(S) = 1 / (1 + e^−S)`, ограничена `[0,01; 0,99]`. Одно свидетельство с надёжностью `r` даёт уверенность ровно `r`; согласные источники усиливают друг друга, несогласные ослабляют. Вклад в `evidence.contribution` со знаком: плюс — за итоговое значение, минус — против.

**5. Числа** (минуты, дБ, метры) не голосуют. Значение берётся у самого надёжного расчёта; остальные свидетельства только проверяют его: расхождение больше `significant_diff` — «против». Уверенность считается по той же формуле `σ(за − против)`, значение не меняется.

**6. Конфликт и слабое несогласие.** «Против» учитывается, если оно достаточно далеко от значения: для упорядоченного enum расстояние в ступенях не меньше `conflict_steps` (у `noise_night` — 2: `quiet` против `loud`; соседние ступени только снижают уверенность). Пусть `за` — сумма `L` свидетельств за итоговое значение, `против` — сумма `L` далёких свидетельств против него. Порог — параметр `θ` (по умолчанию 1,0).

- `за ≥ θ` и `против ≥ θ` — **конфликт**: два весомых голоса друг против друга. Среднее не берётся, создаётся запись в `conflicts`, на неё отвечает тот, кого дешевле спросить.
- `против > 0`, но меньше `θ` — **`weak_disagreement`**: уверенность уже снижена, конфликта нет. На этапе 5 флаг повышает ценность вопроса отельеру.

Конфликты ищутся только у сущностей, перечисленных в параметрах характеристики (для `noise_night` — фасады: уровень отеля производный от фасада и своего расхождения не даёт).

Характеристики с `value_type` `range` и `text` (`sea_view`, `climate_by_month`) берут сильнейшее свидетельство: значение и уверенность равны его надёжности после поправок.

## Пример

Фасад на улице. Карта шума BCN говорит «громко» (`r = 0,85`, `L = 1,7346`). Отельер с репутацией 0,9 отвечает «тихо» (база 0,8).

1. Надёжность отельера: `0,8 × (0,5 + 0,9) = 1,12`, асимметрия (`quiet` выгодно) `× 0,75 = 0,84`. Вклад `L = ln(0,84 / 0,16) = 1,6582`.
2. `S(loud) = 1,7346 − 1,6582 = 0,0764`, `S(quiet) = −0,0764`. Значение — `loud`, уверенность `σ(0,0764) = 0,519`.
3. Расстояние `quiet` — `loud` равно 2 ступеням, обе стороны весят больше `θ = 1,0` — **конфликт**. Вклады: карта `+1,73`, отельер `−1,66`.

Если же против карты выступает только оценка по OSM (`r = 0,6`, `L = 0,4055`): `S(loud) = 1,7346 − 0,4055 = 1,3291`, уверенность 0,79, вклад «против» 0,41 меньше `θ` — **`weak_disagreement`**, без конфликта.

## Параметры

Лежат в реестре характеристик (`backend/registry/*.yaml`, описание полей — `registry.md`): вид значения, поле значения, порядок ступеней (`ordered`), `conflict_steps`, `conflict_theta` (θ), `significant_diff`, `favorable_values`, `conflict_entities`. База надёжности стратегии, группа независимости и срок годности — там же. В Go остались инварианты движка: множитель асимметрии 0,75, множитель свежести 0,5, репутация новичка 0,5, границы надёжности и уверенности. `collect truth` печатает таблицу числа конфликтов и `weak_disagreement` по `θ` и `conflict_steps`, чтобы выбор параметров проверялся по данным.

## Ограничения

- Репутация (`author_trust`) пересчитывается заново по всем активным свидетельствам автора (`usecase/reputation`, после каждого ответа отельера): `trust = (совпадения + 1) / (всего + 2)` по тем утверждениям, для которых есть независимое свидетельство другого автора или источника с `r ≥ 0,8` (`domain.JudgeClaim`). Если вес автора изменился, его факты пересобираются.
- Свидетельства людей в базе пока отсутствуют, поэтому на данных этапа 3 работают только расчёты; людей проверяют тесты на разобранных примерах.
- Асимметрия задана для `noise_night` и для `sea_view` на уровне категории номеров (название «Sea View» как утверждение отеля, `rooms.md`); у категории пониженный порог `θ = 0,3` (`conflict_theta_hotelier`) только в споре с участием утверждения отельера, иначе обычный `θ = 1,0`. `conflict_theta` категории ловит спор о значении; приукрашивание автора ловится дополнительно репутацией (задача 5.2): расхождение утверждений отельера с независимым свидетельством надёжностью `r ≥ 0,8` (сила расхождения не важна) снижает его `trust` независимо от θ. Пример: «Sea View» против расчёта `none` с `r = 0,85` — `trust` 0,50 → 0,33, уверенность «питомцы разрешены» от этого отельера 0,60 → 0,50.

## Почему конфликт закрылся

Конфликты пересоздаются при каждой пересборке факта. Если прежний конфликт не открылся заново, `conflicts.resolution` (текст) и `resolution_kind` (миграция `0022`) получают причину, посчитанную `domain.ExplainClosedConflict` по вкладам движка (только чтение, ничего не пересчитывается):

| `resolution_kind` | Смысл |
|---|---|
| `agreed` | все свидетельства теперь за одно значение: стороны сошлись |
| `weight_dropped` | противоположная сторона осталась, но её вклад ≈ 0 (надёжность после поправок не выше 0,5), чаще всего из-за упавшей репутации автора: спор снят **в пользу расчёта**, а не «сошёлся» |
| `below_threshold` | противоположная сторона ещё весит, но меньше порога θ: остаётся `weak_disagreement` |
| `evidence_removed` | свидетельства сняты, факта больше нет |

Пример: «Sea View» отеля 326. Ответ приукрашивающей персоны снижает доверие 0,50 → 0,33, надёжность его слова 0,8 · (0,5 + 0,33) · 0,75 = 0,50, вклад 0 — `weight_dropped`.
