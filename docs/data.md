# Данные: откуда, как получены, лицензии

Сырые выгрузки лежат в `data/raw/` (в gitignore). В git попадёт только `data/demo/seed.sql.gz`.
Все выгрузки воспроизводятся командами `cmd/collect`.

## OpenStreetMap (Overpass API)

- **Что:** отели (`tourism=hotel`), здания (`building=*`, с `building:levels` и `height`), береговая линия (`natural=coastline`).
- **Откуда:** публичные зеркала Overpass: `overpass-api.de`, затем `overpass.kumi.systems`, `maps.mail.ru`. Запросы идут с осмысленным `User-Agent`, иначе серверы отвечают 406/429.
- **Когда:** 24.10.2026.
- **Как воспроизвести:** `docker compose up -d db`, затем `cd backend && go run ./cmd/collect osm`. Команда идемпотентна: здания и отели обновляются по `osm_id`, береговая линия заменяется целиком.
- **Лицензия:** ODbL 1.0, © участники OpenStreetMap. При публикации нужна атрибуция «© OpenStreetMap contributors».

Запросы (границы `S,W,N,E`, районы из `internal/domain/geo.go`, контуры примерные):

| Данные    | Запрос Overpass QL                                                              | Область                                    |
| --------- | ------------------------------------------------------------------------------- | ------------------------------------------ |
| Отели     | `nwr["tourism"="hotel"](bbox);out center tags;` для каждого из трёх районов     | Барселонета, Готический квартал, Эшампле   |
| Здания    | `way["building"](bbox);out geom tags;`                                          | объединение районов + 0,003° (~300 м)      |
| Береговая | `way["natural"="coastline"](bbox);out geom;`                                    | объединение районов + 0,01° (~1 км)        |

Результат на 24.10.2026: 172 отеля (Барселонета 3, Готический 84, Эшампле 85), 10 640 зданий, 19 отрезков береговой линии.

Правила разбора:

- Отель без `name` и отель-relation пропускаются; район определяется по точке (для way — по центру).
- `osm_id` отеля-way хранится с минусом: id узлов и путей в OSM пересекаются.
- Высота здания: `height` → `osm_height`; иначе `building:levels` × 3 м → `osm_levels`; иначе 15 м → `default`. Футы и нечисловые значения игнорируются.
- Отель-way связывается со зданием с тем же id; отель-узел — со зданием, в которое попадает точка.

Известные ограничения:

- Здания-relation (мультиполигоны) пока не загружаются, внутренние дворы (дырки) тоже. Из-за этого 70 из 172 отелей не привязаны к зданию.
- У 3 218 из 10 640 зданий высоты в OSM нет (`default`).
- В Барселонете в OSM мало отелей с `tourism=hotel` (в расширенном bbox тоже 4–5).

## Демо-подмножество отелей

В БД лежат все 172 отеля, но для демо нужно 40–60. Команда `go run ./cmd/collect select-demo` выставляет `hotels.demo = true` у 50 отелей:

- все отели Барселонеты (их мало, а нужен вид на море);
- остальные места делятся поровну между Готическим кварталом и Эшамплем по кругу;
- внутри района раньше идут отели со зданием и известной высотой, затем со зданием, затем остальные; при равенстве — меньший id.

Результат: Барселонета 3, Готический 23, Эшампле 24; у 47 из 50 есть здание. Отбор детерминирован.

## Мок базовых карточек

Звёзды, цена за ночь, завтрак, Wi-Fi и категории номеров **сгенерированы скриптом** (`go run ./cmd/collect mock-cards`) и не отражают реальные отели. Значения детерминированно зависят от `osm_id`; в `hotels.card` стоит `"mock": true`. Организаторы разрешили мокать базовые характеристики карточки Островка.

## Кадастр Испании (Catastro, INSPIRE Buildings): проверен, не загружен в БД

- **Что:** контуры зданий и этажность (`numberOfFloorsAboveGround`) по муниципалитету Барселона (код 08900).
- **Откуда:** ATOM-сервис загрузки Dirección General del Catastro. Индекс: `https://www.catastro.hacienda.gob.es/INSPIRE/buildings/ES.SDGC.bu.atom.xml` → территориальный офис 08 → `https://www.catastro.hacienda.gob.es/INSPIRE/Buildings/08/08900-BARCELONA/A.ES.SDGC.BU.08900.zip`. Датасет обновлён 21.08.2026.
- **Когда:** скачан 24.10.2026, 49,7 МБ, лежит в `data/raw/catastro/` (в gitignore).
- **Лицензия:** свободное использование при указании автора и владельца данных: Dirección General del Catastro (Ministerio de Hacienda). Атрибуцию нужно показать в README и в UI.
- **Формат:** zip с тремя GML (ISO-8859-1, система координат EPSG:25831 — та же, что выбрана для метровых расчётов): `building.gml` (338 МБ), `buildingpart.gml` (815 МБ), `otherconstruction.gml`, плюс метаданные. Разбирать нужно потоком, целиком в память не грузить.
- **Где этажность:** в `building.gml` поле `numberOfFloorsAboveGround` пустое (`nil`) у всех 10 096 зданий района охвата. Она заполнена в `buildingpart.gml`: у 100% из 48 851 частей. Этажность здания — максимум по его частям (id части `<refcat>_partN`).
- **WFS не годится:** `wfsBU.aspx` отдаёт здания только по кадастровой ссылке или id, выборки по рамке нет; `wfsCP.aspx` для участков тоже. Для района охвата нужна именно ATOM-выгрузка.

Проверка на отелях (разовый скрипт, не в репозитории): отель сопоставлялся со зданием кадастра по попаданию точки в контур.

| Показатель                                            | OSM        | Кадастр        |
| ----------------------------------------------------- | ---------- | -------------- |
| Отелей со зданием (все 172)                           | 102 (59%)  | 157 (91%)      |
| Отелей со зданием и этажностью (все 172)              | 80 (47%)   | 157 (91%)      |

Из 50 демо-отелей здание кадастра с этажностью найдено у 47 (94%).

Согласованность этажности на 75 отелях, где она есть и в OSM (`building:levels`), и в кадастре: точно совпала у 60 (80%), в пределах ±1 этажа у 68 (91%). Расхождения почти всегда в одну сторону: в OSM этажей меньше (разность от −4 до −1 у 14 отелей, +1 у одного).

Выводы:

- Кадастр — основной источник высоты (`height_source = catastro`), уверенность 0,8–0,9 по разделу 6 PROJECT_CONTEXT.md; высота в метрах = этажи × 3 м.
- Заодно кадастр закрывает пробел OSM: контуры зданий-relation и дворов, из-за которых 70 отелей остались без здания.
- OSM `building:levels` остаётся вторым источником: расхождение больше порога даёт конфликт (этап 3).
- Загрузка кадастра в `buildings` — отдельная задача: потоковый разбор GML, перепроекция EPSG:25831 → 4326, сопоставление с контурами OSM. Нужна на этапе 2 (вид на море).

## Стратегическая карта шума Барселоны (Open Data BCN): проверена, не загружена в БД

- **Что:** уровни шума в дБ по фасадам зданий и по участкам улиц, за день (Ld), вечер (Le), ночь (Ln) и сутки (Lden), с разбивкой по источникам: всего, дорожное движение, железная дорога, промышленность, ночная жизнь (`Oci_Ln`), пешеходы, дворы.
- **Откуда:** каталог Open Data BCN (CKAN API `https://opendata-ajuntament.barcelona.cat/data/api/3/action/package_show?id=<набор>`), набор «Noise maps by facade» (`facanes-mapa-estrategic-soroll`, метаданные обновлены 18.03.2025) и «Noise maps by street section» (`tramer-mapa-estrategic-soroll`, 18.02.2025). Данные карты — 2017 год (карта обновляется раз в 5 лет; растры и изофоны 2022 года тоже есть, но для фасадов их нет).
- **Файлы** (скачаны 24.10.2026 в `data/raw/noise/`, в gitignore):
  - `2017_Facanes_Mapa_Estrategic_Soroll_BCN.gpkg`, 173,9 МБ — https://opendata-ajuntament.barcelona.cat/data/dataset/8aeb17f9-651a-42e0-9e6d-9f4a55a5b2ea/resource/96d801d9-f2a5-495f-87cb-e02bce890102/download/2017_facanes_mapa_estrategic_soroll_bcn.gpkg
  - `2017_Tramer_Mapa_Estrategic_Soroll_BCN.gpkg`, 14,4 МБ — https://opendata-ajuntament.barcelona.cat/data/dataset/34fb5caa-d1bb-40ae-b0f4-d5ea531555ae/resource/f7e77a6e-6f84-474e-aa48-9e5bd6ecab43/download/2017_tramer_mapa_estrategic_soroll_bcn.gpkg
- **Лицензия:** Creative Commons Attribution 4.0. Атрибуцию («Ajuntament de Barcelona, Mapa Estratègic de Soroll») нужно показать в README и в UI.
- **Формат:** GeoPackage (SQLite), система координат EPSG:25831, как у кадастра.
  - Фасады: 257 475 сегментов (MULTILINESTRING), поле `ref_cadastral` (14 знаков, та же кадастровая ссылка, что у зданий INSPIRE), вещественные `Total_Ld/Le/Ln/Lden`, `Transit_viari_*`, `Transit_ferroviari_*`, `Industria_*`, `Oci_Ln` и др. Пропусков в `Total_Ln` нет.
  - Участки улиц: 17 958 линий (LINESTRING), числа хранятся строками (`TOTAL_N`, `TOTAL_DEN`, …), поле `TRAM`. Подходит под `noise_segments`, но фасадов эти данные не различают.

Проверка на отелях (разовый скрипт, не в репозитории): отель → здание кадастра (см. выше) → фасадные сегменты по `ref_cadastral`.

| Показатель                                                       | Все (172)  | Демо (50) |
| ---------------------------------------------------------------- | ---------- | --------- |
| Найдено здание кадастра                                          | 157        | 47        |
| Есть фасадный шум                                                | 156 (91%)  | 46 (92%)  |
| Фасадов на здание, медиана                                       | 2          | 2         |
| Разброс Ln между фасадами одного здания, медиана / максимум      | 21,6 / 31,0 дБ | 21,4 / 26,5 дБ |
| Зданий с разбросом Ln ≥ 5 дБ                                     | 81%        | 78%       |

Распределение `Ln` по всем фасадам города: p10 = 35, медиана 47,3, p90 = 61,3 дБ, максимум 83 дБ.

Выводы:

- `noise_night` можно считать по фасадам с источником `bcn_noise` и уверенностью 0,85 (в реестре из раздела 7 так и заложено); данные привязаны к зданию через `ref_cadastral`, поэтому нужен кадастр как мост к отелям.
- Разница между улицей и двором в одном здании — медиана 21,6 дБ. Это основа для «тихий номер во двор» и для вопроса отельеру, какие категории номеров на какой фасад выходят.
- `Oci_Ln` (шум ночной жизни) даёт готовую оценку «рядом бары и клубы» без самостоятельного разбора POI; медиана максимума по отелю 36,4 дБ, максимум 68,1 дБ.
- Для конфликтов нужен независимый второй источник: карта шума и OSM-оценка (класс дорог, бары в радиусе) независимы, а фасады и участки улиц — нет (одна модель 2017 года).
- Данные расчётные (модель), не измерения, и им уже 9 лет: срок годности факта в реестре ставить с оговоркой, в evidence писать год карты.
- Ограничение: у 16 отелей (9%) нет здания кадастра или фасадов, для них `noise_night` останется только по OSM-оценке (уверенность ниже) либо вопросом отельеру.
- Загрузка: GPKG читается как SQLite, геометрия — GPKG-заголовок + WKB в EPSG:25831. Потребуется чистый Go-драйвер SQLite (например, `modernc.org/sqlite`, без CGO) или одноразовая конвертация через `ogr2ogr`; в БД достаточно сегментов зданий района охвата. Отдельная задача на этап 3.
